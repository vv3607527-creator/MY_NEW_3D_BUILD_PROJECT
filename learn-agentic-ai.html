The agent loop is all there is

Every agent — from a coding assistant to an autonomous researcher — runs the same core cycle. Master these five moves and everything else is composition.

Perceive

The agent takes in its context: user intent, environment state, prior results, and available signals.

Reason

An LLM weighs the goal against what it knows, decomposing the problem into tractable sub-problems.

Plan

It selects a strategy — which tools to call, in what order, with what arguments, and when to stop.

Act

Actions execute in the real world: API calls, code runs, file edits, database queries, messages sent.

Reflect

It evaluates outcomes against the goal, stores lessons in memory, and loops again until satisfied.

Five parts bolt an LLM onto reality

A raw language model only predicts text. These components turn prediction into agency.

The model — the reasoning core

GPT-class, Claude-class, or open models like Llama and Qwen. The model is the brain: everything else exists to feed it context and carry out its decisions.

reasoningfunction callingstructured output

Tools

Typed functions the model may call — web search, code execution, APIs, file systems. Tools are how thought becomes action.

Memory

Short-term context windows plus long-term vector stores. Memory lets an agent learn across steps and sessions instead of starting cold.

Orchestration

The runtime loop that sequences perception, tool calls, and retries. Frameworks live here — the graph that routes state between steps.

Guardrails & evaluation

Permission scopes, spend limits, sandboxing, and eval suites. Autonomy without constraints is just an expensive way to break things.

Design patterns you'll meet in the wild

From Anthropic's Building Effective Agents to the latest research, most architectures reduce to five recurring shapes.

P·01

Prompt chaining

Break a task into fixed steps; each output feeds the next. Simple, predictable, easy to debug.

P·02

ReAct — reason + act interleaved

The canonical loop: think, call a tool, observe the result, think again. The default shape of most agents.

P·03

Planner–executor

A planner decomposes the goal into a task graph; cheap executors handle each node in parallel.

P·04

Reflection & self-critique

A critic pass reviews drafts or traces and demands revisions — measurable quality gains for a latency cost.

P·05

Multi-agent teams

Specialized agents negotiate over shared state — researcher, coder, reviewer. Powerful, but coordination overhead is real.

Your path from curious to shipping

Six stages, roughly one to two months each if you build alongside reading.

Stage 01 · Week 1–2

Foundations

Get fluent with the primitive everything rests on: prompting, tokens, temperature, context windows, and structured JSON output.

  • prompt engineering
  • tokens & context
  • JSON mode
  • API basics
Stage 02 · Week 3–4

Tool calling

Teach a model to call functions. Build a tiny weather bot that answers by invoking real APIs — no framework yet, raw HTTP.

  • function calling
  • schema design
  • error handling
Stage 03 · Month 2

First real agent

Write the ReAct loop yourself in ~100 lines: goal in, tool calls out, results fed back, stop condition enforced.

  • ReAct pattern
  • stop conditions
  • retry logic
  • tracing
Stage 04 · Month 2–3

Memory & retrieval

Add persistence: embeddings, vector databases, RAG. Your agent now recalls yesterday's work and cites its sources.

  • embeddings
  • vector search
  • RAG pipelines
  • chunking strategy
Stage 05 · Month 3–4

Advanced patterns

Planner–executor graphs, reflection passes, and multi-agent handoffs. Learn when complexity pays for itself — and when it doesn't.

  • agent graphs
  • reflection
  • multi-agent
  • evals
Stage 06 · Ongoing

Production craft

Sandboxing, permission scopes, cost budgets, observability, and continuous evaluation. This is where agents earn trust.

  • guardrails
  • observability
  • cost control
  • safety review
